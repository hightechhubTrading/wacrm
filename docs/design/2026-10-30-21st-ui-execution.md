# 21st UI review: implementation record

30–31 October 2026. This records the implementation of the evidence-backed fixes and the expressive visual direction chosen by the user in [the review plan](2026-10-30-21st-ui-review-plan.md).

## Changes made

- Associated all deal editor labels with their inputs and selects through instance-safe IDs in `src/components/pipelines/deal-form.tsx`. Native selects and the inline flow editor fields now show explicit `focus-visible` outlines.
- Replaced the stage color overlay in `src/components/pipelines/pipeline-settings.tsx` with the existing Base UI popover. Both existing-stage and new-stage color choices now have localized accessible names, a selected state, and larger targets. The popover closes on Escape and returns focus to its trigger.
- Applied reduced-motion duration rules to dashboard descendants in `src/app/globals.css` and `src/app/design-system.css`; the workday widget also avoids its animation sync listener when reduced motion is active.
- Localized visible and accessible strings in the flow editor toolbar in both catalogs. The dashboard loading string and sidebar navigation label listed in the original plan were already localized in the current worktree and needed no edit.
- Increased essential dashboard metric, section, chart, team and activity text to the documented minimum metadata/section sizes. Phone editing controls now use 16px text, including controls in portaled sheets and dialogs.
- Applied the chosen expressive direction to the dashboard and pipeline board: a tinted welcome area, stronger metric scale and tonal surfaces, stage-color framing, attention edges and quieter empty AI summaries. The configured stage colors and six saved theme accents remain the source of color. No deal actions or data flow changed.
- Reworked the phone header after a 200% root-text-size check showed that the page title disappeared behind the language and appearance controls. The phone language switch is now one labeled button showing the destination language; the full two-choice switch remains on wider screens. The header wraps its controls only when needed, keeping the normal 390px layout on one row and the enlarged-text title visible.
- Replaced the viewer's Quotations load-error loop with a localized access state. The Quotations APIs intentionally require agent access, so viewers now see a clear explanation and no creation/retry controls instead of a failing request. Authorized quotation behavior is unchanged.
- The rendered accessibility sweep found an unnamed Quotations product-code control, unnamed Contacts row-action and pagination buttons, low-contrast Contacts tag text, and a low-contrast Flows Beta badge. Added localized control names, used readable foreground text with a small configured-color dot for tags, and moved the badge to the existing semantic warning token.
- The final completion audit found two remaining English-only Contacts screen-reader labels in Arabic mode: removing a tag filter and selecting a contact row. Both now use translated catalog messages.

## Remaining work and decisions

- The production fixture uses a synthetic account. The user chose browser evidence only for this review, so physical iOS Safari is recorded as a limitation rather than a completion gate. Physical browser text zoom, complete loading/failure/read-only state coverage in the authenticated shell, keyboard navigation on every route and real customer data remain outside this run. Playwright WebKit is not installed and no iOS Simulator is available in this environment.
- The pipeline route reports document widths above the viewport from its five-column board at 360–1440px; its board container remains within the main content and scrolls locally. Playwright's default Arabic pipeline screenshot was blank at 390px, but Chrome DevTools viewport capture rendered the route correctly in both light and dark (`pipelines-cdp-390-ar-*.png`). The header remained hit-testable at the expected position. This was a capture artifact; no layout CSS change was made from it.
- The user selected a more expressive direction. The choice is recorded in `.21st/design.json`. Navigation labels/expansion, major pipeline card-density changes, and whether to keep the normal-motion dashboard mascot remain separate product calls and were not changed by the visual pass.
- The earlier isolated Arabic edge clipping was not reproduced as missing content in the production viewport captures. Continue to check scroll behavior on a physical device, especially the pipeline board.
- The expressive styling was checked on the representative Dashboard/Pipeline screens. The rendered route matrix and accessibility sweep above close the browser evidence gate chosen by the user. Loading/failure/read-only coverage is focused on the existing recovery, viewer, composer and sales fixtures; exhaustive customer-data and physical-device verification remain outside this review.
- **Product decisions to review:** the phone Contacts and Quotations tables could gain a clearer horizontal-scroll cue or switch to cards; Pipeline card density and contextual action priority need a staff task comparison; the normal-motion workday mascot, optionally expanded navigation rail and degree of AI-summary emphasis are visual/product choices. No high-confidence defect warrants changing those workflows in this pass.
